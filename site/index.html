02 / WHY VIM?

A small editor test
with a bigger signal.

Vim is not the point. Reliable tool use is.

Vim turns editing into a compact language of actions: move, select, change, repeat, save. To solve a task, an LLM must translate intent into an exact sequence, track state, and stop with the right result. Those are the same habits a useful coding agent needs when it edits your files, calls tools, or carries out a multi-step instruction.

This makes vimbench a focused test of execution reliability, not a claim that Vim knowledge equals intelligence. Every answer is run, every final buffer is checked, and short correct solutions are rewarded. There is no judge model deciding whether an answer “looks right.”

SIGNAL 01

Exactness

A high pass rate means the model more often turns a clear request into the exact requested state—fewer almost-right edits for you to repair.

SIGNAL 02

Efficiency

Efficient solutions use fewer actions. For everyday agents, that can mean shorter traces, less opportunity for drift, and lower tool overhead.

SIGNAL 03

Recovery signal

Partial credit shows how close failures get. It helps distinguish a near miss from a model that leaves the document badly mangled.

FOR EVERYDAY USERS

Use it as one decision signal, not the whole decision.

Choose a model with strong pass rate when dependable file edits matter. Use efficiency to break ties between similarly accurate models, then weigh price, speed, context window, privacy, and performance on your own tasks. A model that wins vimbench may still be the wrong choice for writing, research, vision, or conversation.

03 / METHOD

Small loop. Hard signal.

Every score comes from executable behavior,
not another model’s opinion.

01

Prompt

The model sees a start buffer, target buffer, natural-language instruction, and keystroke notation.

02

Replay

Its answer is translated to bytes and replayed in clean, headless Vim with shell access disabled.

03

Compare

The saved buffer is compared byte-for-byte with the target. Correct answers are scored for keystroke efficiency.

model output→keystroke bytes→vim -u NONE→exact diff
